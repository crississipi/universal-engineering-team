Task Completion Reporting & Role-Skill Orchestration

Source: docs/agent-execution/TASK-COMPLETION-REPORTING.md; schema: schemas/executions/task-completion-report.schema.json

Completion-triggered lifecycle

flowchart TD
  Prompt[Top-level user task] --> Identity[Create execution ID]
  Identity --> Select[Select smallest sufficient canonical roles]
  Select --> Skills[Read selected role SKILL.md files]
  Skills --> Execute[Execute and coordinate owned work]
  Execute --> Verify[Record actual verification evidence]
  Verify --> Terminal[Set completed / warnings / blocked / failed]
  Terminal --> Report[Generate one consolidated report]
  Report --> Store[Persist JSON and Markdown]

VS Code Copilot runtime integration

.github/skills/ contains generated project skill mirrors from canonical skills/. scripts/sync-copilot-skills.py keeps the copies synchronized.

.github/hooks/task-completion-reporting.json captures prompt-start metadata and uses the Copilot agentStop event to require a structured report input, then invokes the report generator. Runtime state and pending drafts are stored under the gitignored .copilot-runtime/ directory.

The VS Code hooks experience is Preview. The hook validates structure and identity but cannot independently prove role-skill activation, work performed, or verification claims. It has a bounded retry fallback that must be disclosed if triggered.

Report artifacts

  • scripts/report-task-completion.py validates and renders one terminal task report.
  • schemas/executions/task-completion-report.schema.json defines the structured report contract.
  • Output: reports/task-completions/<execution_id>/report.json and report.md.
  • Each report records actually activated roles, loaded canonical skills, contributions, deliverables, verification, decisions, issues, and next steps.

Ingress security logging

scripts/log-ingress-security-event.py appends sanitized JSONL metadata for invalid signatures and unparseable webhook payloads. Raw bodies, secrets, authorization headers, and full signature values are excluded. Retention and access policy remain deployment decisions for Security and Operations.

Reporting occurs after each top-level task reaches a terminal outcome. It is not daily, timezone-bound, or time-threshold-driven. The generator validates supplied evidence; it cannot independently prove that a skill was loaded or a task was performed.
